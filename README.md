# NetProbe

Поиск IP неизвестного устройства со статикой, его шлюза и остальных соседей + настройка IPv4 на своей карте.

## Что запускать
| файл | размер | требования |
|---|---|---|
| `dist\NetProbe.exe` | 13 МБ | **ничего**: ни Python, ни Npcap, ни .NET. Любая Windows 7+ x64 |
| `dist\NetProbe-Npcap.exe` | 66 МБ | то же + если на машине окажется Npcap, включится полный L2-режим |

Оба запускаются **без прав администратора** (UAC-манифеста нет специально — иначе на машине без прав exe вообще не стартовал бы). В окне сразу выводится список того, что доступно на этой машине, и кнопка «Перезапустить от администратора».

## Что работает без админа
- перечисление адаптеров — `iphlpapi.GetAdaptersAddresses` (имя, описание, IP/префикс, MAC, up/down);
- опрос ARP-кэша, приём UDP-широковещания (DHCP / NBNS / mDNS / LLMNR / SSDP / WSD);
- ARP-скан подсети через `iphlpapi.SendARP`, 32 потока — 62 хоста за ~7 с (проверено);
- ping-скан и TCP-пробой как фолбэки;
- SSDP M-SEARCH → находит UPnP-InternetGatewayDevice, т.е. маршрутизатор.

## Что требует админа
- promisc-захват `SIO_RCVALL` (даёт весь IPv4-трафик чужих хостов);
- назначение IP и временный IP для скана чужой подсети;
- Npcap-режим (сам Npcap ещё и надо установить).

Без админа адрес устройства всё равно находится пассивно — просто медленнее и без транзитного трафика.

## Почему Npcap нельзя вшить в exe
Это драйвер уровня ядра: своя установка, подпись, служба, права администратора. В портативный exe он не упаковывается ни в каком виде. Поэтому основной движок обходится штатными API Windows: raw-сокет, iphlpapi, netsh, arp, route, ping.

| | Портативный (по умолчанию) | Npcap |
|---|---|---|
| Пассив | `SIO_RCVALL` + UDP-широковещание + ARP-кэш | полный L2-захват, включая чужие ARP |
| Скан | `SendARP` → ping → TCP | собственные ARP-пакеты |
| Свой IP в подсети | нужен (добавляется временно, снимается после) | не нужен |
| Шлюз | подтверждение через `route add` / UPnP-IGD / DHCP / `.1`,`.62` | L2-next-hop транзита — пассивно и точно |

## Порядок работы
1. Подключить ПК к устройству (напрямую или в тот же коммутатор).
2. Выбрать интерфейс, движок «авто».
3. СКАНИРОВАТЬ: пассив N секунд → подсеть /26 (маска настраивается, проверяется по общему префиксу адресов и direct-broadcast `x.x.x.63`) → скан всех 62 хостов → шлюз по приоритету: подтверждён маршрутизацией → L2-next-hop → UPnP-IGD/DHCP → частый ARP-таргет → `.1`/`.62`.

Галка «разрешить временный IP» — адрес из найденной подсети добавляется вторым (`netsh add address`), проверяется на конфликт и снимается после скана.
Галка «проверять шлюз» — `route add 8.8.8.8 mask 255.255.255.255 <кандидат>` → ping → `route delete`. Маршрут по умолчанию не трогается.

## Настройка IPv4 (нижняя панель)
- Автоматически (DHCP)
- Статический — по умолчанию `129.9.255.254 / 255.255.0.0`, шлюз не задаётся
- Свободный адрес из найденного диапазона (заполняется после скана)
- «добавить вторым адресом» → `netsh add address`, текущая конфигурация сохраняется

`netsh` вызывается по FriendlyName, при неудаче — по индексу интерфейса (спасает от локализованных имён).

## Сборка
```
build.bat
```
`selftest.py` — headless-проверка портативного движка.

## Если устройство молчит
- увеличить время прослушивания до 120–300 с;
- перезагрузить устройство при подключённом кабеле (при старте почти всегда шлёт ARP/DHCP);
- вписать предполагаемый адрес в поле «Подсказка».

## Возможные помехи в корпоративной среде
- SmartScreen/антивирус на неподписанном exe — при необходимости подписать сертификатом организации;
- Windows Firewall может резать входящий UDP → пассивная фаза беднее, но `SendARP`/ping-скан не зависят от входящих правил.
